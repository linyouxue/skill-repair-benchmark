=======================

Repository: /home/travis/build/failed/google/auto
Target CI toolchain (per .travis.yml): openjdk7 / oraclejdk7
Reproduced locally with: openjdk 1.7.0_75 (via /opt/jdk_switcher)
CI command:
  mvn -Dhttps.protocols=TLSv1.2 -B -U -f build-pom.xml verify \

Reactor summary (reproduction under JDK 7):
  Auto (Parent)              SUCCESS
  Auto Common Libraries      SUCCESS
  AutoFactory                SUCCESS
  AutoService                SUCCESS
  AutoValue                  FAILURE  <-- maven-invoker-plugin integration-test
  build-only                 SUCCESS

Failing nested build (Maven Invoker):
  value/src/it/functional/pom.xml  (artifactId: functional)

First concrete errors in value/target/it/functional/build.log (test-compile):

  1) com.google.common.base.MoreObjects cannot be resolved in test sources:
       AutoValueTest.java:[20,30] cannot find symbol: class MoreObjects
       AutoValueTest.java:[72,16] package MoreObjects does not exist
       AutoValueTest.java:[72,49] cannot find symbol variable MoreObjects
     Root cause: MoreObjects was added in Guava 18, but is pulled in only
     transitively via guava-testlib. The functional POM declares
     guava-testlib:18.0, which pre-dates the API shape expected by the
     synchronized AutoValue functional tests. The repair is a coherent,
     version-synchronized dependency set for the integration project.

  2) unmappable character for encoding ASCII in multiple test sources
     (e.g. "@author emcmanus@google.com (Éamonn McManus)").
     Root cause: value/src/it/functional/pom.xml is a standalone Maven
     Invoker POM. It has NO <parent> and therefore does NOT inherit
     project.build.sourceEncoding = UTF-8 from the repository parent pom.xml.
     Under the Travis JDK 7 environment, the JVM default file.encoding is
     ASCII, so javac rejects the UTF-8 source files.

Scope of repair
---------------
Both failures are inside the single Maven Invoker POM
value/src/it/functional/pom.xml. No other module is broken under the
target JDK 7 toolchain. The parent reactor and the production AutoValue
module compile and test fine. The repair is scoped to this one POM.

Planned changes to value/src/it/functional/pom.xml
--------------------------------------------------
A. Dependency synchronization (version drift):
   - com.google.code.findbugs:jsr305      1.3.9 -> 3.0.0  (scope: provided)
   - junit:junit                          4.11  -> 4.12   (scope: test)
   - add com.google.guava:guava           19.0            (scope: test)
   - com.google.guava:guava-testlib       18.0  -> 19.0   (scope: test)
   - com.google.truth:truth               0.25  -> 0.28   (scope: test)

B. Encoding configuration for the standalone Invoker POM:
   - Add <encoding>UTF-8</encoding> to the maven-compiler-plugin
     configuration (both the default build block and the eclipse profile),
     so UTF-8 source files compile regardless of JVM default encoding on
     the target CI machine.
