integration-test projects under value/src/it/*. The gwtserializer project

Root cause 1 (encoding): The invoker-test pom at
`value/src/it/functional/pom.xml` is a free-standing project (no <parent>
pointing at auto-parent), so it does not inherit the parent pom's
`<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>`.
Many source files (e.g. SimpleValueType.java, AutoValueTest.java,
MyEnum.java) have the UTF-8 `É` byte sequence in the "@author Éamonn
McManus" Javadoc. Maven then falls back to the JVM default
(`file.encoding=ANSI_X3.4-1968` on this host), so javac reports
`unmappable character for encoding ASCII` and treats these as warnings
in main/ but surfaces them alongside the hard error in test/.

Root cause 2 (missing guava class): AutoValueTest.java imports
`com.google.common.base.MoreObjects`, which was introduced in Guava 18.
The functional invoker-test pom declares (in this order):

    truth 0.25            (-> transitively depends on guava 17.0)
    guava-testlib 18.0    (-> transitively depends on guava 18.0)

Both guavas are at depth 2 in the test's resolution graph. Maven's
"first-declared wins" tie-break picks guava-17.0 (via truth), as
`dependency:tree` confirms:

    +- com.google.truth:truth:jar:0.25:test
    |  \- com.google.guava:guava:jar:17.0:test
    \- com.google.guava:guava-testlib:jar:18.0:test

Guava 17.0 does not contain MoreObjects, so the test fails to compile.
(This is the pre-existing bug the project's own ad-hoc test matrix
exposes; see origin/pr/178 which attempted something similar and was
not merged.)

Both root causes live in build configuration (one pom file), not in
Java source.

Fix plan (one file: value/src/it/functional/pom.xml):

1. Add `<properties><project.build.sourceEncoding>UTF-8</project.build.sourceEncoding></properties>`
   so javac reads the UTF-8 source files correctly.

2. Add an explicit direct test-scoped dependency on guava 18.0, placed
   as the first dependency inside <dependencies> block (or before truth)
   so it is at depth 1 and wins the resolution over truth's transitive
   guava 17.0. This makes `com.google.common.base.MoreObjects` available
   on the test classpath.

Nothing else in the repo needs to change. The gwtserializer invoker
project already passes.
