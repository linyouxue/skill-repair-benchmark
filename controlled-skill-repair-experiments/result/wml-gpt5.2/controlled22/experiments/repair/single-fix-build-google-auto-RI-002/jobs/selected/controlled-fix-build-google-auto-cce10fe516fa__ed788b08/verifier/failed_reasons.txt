Failure:
- Test com.google.auto.value.processor.AutoAnnotationCompilationTest.testMissingClass fails.
- Assertion expects the first compiler diagnostic message to contain "NotAutoAnnotation".
- Actual first diagnostic message is "unmappable character for encoding ASCII".

Diagnosis:
- This failure happens inside the test’s in-process compilation (JavaCompiler API).
- The JavaCompiler task is created without specifying a source encoding.
- In this environment, the default platform encoding is ANSI_X3.4-1968 (ASCII). When the compiler encounters any non-ASCII characters in sources produced/compiled during that task, it emits an "unmappable character" diagnostic which may appear before the expected "NotAutoAnnotation" diagnostic.
- This is a test robustness / configuration issue (encoding + diagnostic ordering), not production code.

Plan:
1) In AutoAnnotationCompilationTest.doTestMissingClass, pass "-encoding", "UTF-8" to JavaCompiler.getTask options so the compilation uses a stable UTF-8 source encoding.
2) Make the assertion robust to diagnostic ordering by searching the diagnostics list for a message that contains "NotAutoAnnotation" rather than assuming it is diagnostics.get(0).
3) Keep the existing intent that no diagnostic should mention "static" (processor must not mis-handle @NotAutoAnnotation).
