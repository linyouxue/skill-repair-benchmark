Repository: /home/travis/build/failed/google/auto
Environment: Maven 3.6.3; Java 11.0.27

What fails
- The project uses maven-invoker-plugin in the value module.
- The invoker runs nested Maven builds from value/src/it/*/pom.xml.
- The failing nested build is: value/src/it/functional/pom.xml.

First concrete error
When running the nested build directly, Maven fails to resolve or compile due to stale dependency configuration in the integration-test POM (dependency/version drift compared to what the integration tests expect).

Root cause
The functional integration test POM had outdated and incompatible test dependencies:
- com.google.code.findbugs:jsr305 was 1.3.9
- junit:junit was 4.11
- com.google.truth:truth was 0.25
- com.google.guava:guava-testlib was 18.0
- There was no direct com.google.guava:guava dependency, so Guava APIs used by test libs can be missing depending on mediation.

Fix plan
Update value/src/it/functional/pom.xml to a coherent, synchronized test dependency set:
- jsr305 -> 3.0.0 (provided)
- junit -> 4.12 (test)
- add guava -> 19.0 (test)
- guava-testlib -> 19.0 (test)
- truth -> 0.28 (test)
