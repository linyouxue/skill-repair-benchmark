black — notes for fuzz testing
==============================

Library: /app/black  (installable as `black`)
Runtime deps: click, mypy_extensions, packaging, pathspec, platformdirs,
              pytokens, tomli (py<3.11), typing_extensions (py<3.11)

Primary FUT (fuzz target):
  qualname: black.format_str
  file:line: src/black/__init__.py:1177
  signature: format_str(src_contents: str, *, mode: Mode, lines=())
  import: `import black; black.format_str(src, mode=black.Mode())`
  input type: str (Python source code)
  rationale: this is black's main public reformatting entry point. It
    invokes the full parser (blib2to3 / pytokens) and the pretty-printer,
    exercising the most code and the richest "untrusted input → structured
    AST" boundary in the project. Perfect LibFuzzer target.

Invalid-input exceptions (CAUGHT, early return in harness):
  - black.InvalidInput                        (source is not valid Python)
  - black.parsing.ASTSafetyError              (AST mismatch after format)
  - IndentationError                          (surfaced through blib2to3)
  - SyntaxError                               (python tokenizer rejection)
  - ValueError                                (bad surrogate / NUL input)
  - UnicodeDecodeError, UnicodeEncodeError    (bad text)
  - RecursionError                            (very deeply nested; benign
    for a formatter stress test, not a crash we want to flag)

Real-crash exceptions (PROPAGATE):
  - any other uncaught exception (AssertionError, KeyError, IndexError,
    AttributeError, TypeError, NotImplementedError, etc.).

Oracle: crash-only.

Seeds (fed through FDP as a Unicode string):
  "x=1\n", "def f():\n    pass\n", "class A:\n    pass\n",
  "a,b=1,2\n", "lambda x:x\n", "{'a':1}\n", "f'{x!r}'\n".

Fuzz entry (pseudocode):
  fdp = FuzzedDataProvider(data)
  s = fdp.ConsumeUnicodeNoSurrogates(fdp.remaining_bytes())
  try: black.format_str(s, mode=MODE)
  except INVALID_INPUT_EXCEPTIONS: return
