Applied a single recurring pattern update: **deliverables-gate-before-termination** (anchor: `deliverables-gate`). The failure recurred because the executor sometimes never invokes the TTS skill (zero tool actions), so the existing “Deliverables Gate” rule wasn’t consulted. To make the gate harder to miss, I pushed a lightweight, cross-skill “pre-end-turn deliverables gate” hook into every FFmpeg skill in this batch, and strengthened the TTS gate’s trigger phrasing.

## What changed

### 1) Strengthened trigger in `text-to-speech/SKILL.md`
- Kept the existing **Deliverables Gate (block end-turn)** section and command block.
- Updated the pointer trigger to be more “global” in practice:
  - **Read `references/deliverables-gate.md` when** the task is graded by required output file paths **or when you have not yet created any outputs**.
  - Skip when stdout-only.

File edited:
- `evolved_skills/text-to-speech/SKILL.md`

### 2) Added a minimal Deliverables Gate hook to each FFmpeg skill (top-level)
Each FFmpeg skill now has an early section:

- **Deliverables Gate (block end-turn for file-based graders)**
- Generic existence + ffprobe readability check snippet
- Pointer: `Read references/deliverables-gate.md when the task is graded by presence/paths of output files ... and you are about to end the run. Skip when stdout only.`

Files edited:
- `evolved_skills/ffmpeg-audio-processing/SKILL.md`
- `evolved_skills/ffmpeg-format-conversion/SKILL.md`

- `evolved_skills/ffmpeg-video-editing/SKILL.md`
- `evolved_skills/ffmpeg-video-filters/SKILL.md`

### 3) Avoided broken/orphan pointers by copying the L3 deliverables gate chapter into each FFmpeg skill’s references/
Because each skill is self-contained, and the FFmpeg skills now point to `references/deliverables-gate.md`, I created that file in each FFmpeg references directory (identical content to the TTS version).

New files created:

## Why this addresses the recurrence
The recurrence specifically showed **no skill invocations / no tool actions**, meaning the executor can “miss” a skill-specific gate. By adding the same “block end-turn” hook into *all* FFmpeg skills commonly selected in the dubbing pipeline, the deliverables gate becomes much harder to skip in practice, even if the run selects an FFmpeg skill instead of TTS. The L3 chapter already contains the required structure (runnable Python, a runtime branch, and verification with corrective actions), so the hook reliably routes to a robust procedure.
