Updated the skill to address the recurring workflow failure: finishing without writing any required plan artifacts.

### Changes made

- **`SKILL.md`**
  - Added a **workflow section** “Plan-first workflow” to force early enumeration of required outputs from `problem.json`.
  - Added a **workflow section** “Finalize: persist required plan artifacts” with a concrete “done = all plan_output files written + read-back verified” rule.
  - Added an **L2 → L3 pointer**:
    - `Read references/persist_plan_outputs.md when the task provides problem.json with plan_output paths. Skip when the harness collects plans from stdout instead of files.`
  - Strengthened **Common Pitfalls** to explicitly call out missing outputs / wrong paths / no read-back / treating “no plan” as “no output”.

- **New L3 chapter** `references/persist_plan_outputs.md`
  - Implements a reusable, runnable procedure that:
    - Loads an inventory from `problem.json`
    - Branches on manifest shape (list vs dict with `"instances"`)
    - Branches on `plan is None` (empty-plan convention) vs normal plan rendering
    - Writes each plan to the exact `plan_output` path (mkdir parents)
    - **Verifies** each file exists and matches the chosen convention
    - Prescribes **corrective actions** on verification failure (retry mkdir/write, fix render, rewrite)
    - Final end-of-run verification: all required outputs exist

All pointers are non-broken (new L3 file created) and there are no orphan references.
