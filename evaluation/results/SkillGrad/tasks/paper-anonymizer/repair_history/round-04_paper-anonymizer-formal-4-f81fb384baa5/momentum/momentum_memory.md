### deliverable-enforcement-and-output-verification | workflow | ensure required output artifacts are created at specified paths before ending
- anchor: deliverable-enforcement
- appeared_in: iter_0, iter_1, iter_2, iter_3
- description: The executor can complete a run while failing the grader’s acceptance criteria because required deliverables are missing or written to the wrong filesystem locations. This often presents as an output inventory that is empty or contains files in the working directory (default/local filenames) rather than the explicitly required absolute paths (e.g., `paper1.pdf` instead of `/root/redacted/paper1.pdf`). The core mechanism is a missing “path adherence + existence/validity gate” at the end of the workflow: the executor either never creates the target directory, doesn’t pass the required absolute output path into the save/export call, or ends without verifying that each required artifact exists, is non-empty, and is openable as a PDF. A recurring sub-mechanism is treating the current working directory (`cd`) as determining where tools save outputs; the remedy is to always provide absolute output paths and then verify at those paths.
- latest_executor_action: When the task specifies exact output paths, treat them as hard acceptance criteria. Early: enumerate all required output paths and `mkdir -p` their parent dirs. During export: always pass the exact absolute output path string into the write/save command (never rely on defaults, the current working directory, or relative paths). Before ending: verify for every required path that (1) file exists, (2) size > 0, and (3) it opens as a PDF; additionally run any task-specific invariants (e.g., page count unchanged, text retention threshold). If any check fails, do not end—delete the bad/misplaced output, fix the path/toolchain, and regenerate until all deliverables pass.
