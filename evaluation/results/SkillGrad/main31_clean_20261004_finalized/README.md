# MAIN31 clean experiment publication

This directory publishes eleven distinct result chains from MAIN31. It is separate from the earlier representative archive in `evaluation/results/SkillGrad/tasks/`. The original nine LOCAL entries are preserved byte-for-byte from the prior publication. Two additional SERVER tasks are included because they were independently audited as ACCEPT.

## Published scope

| Group | Tasks | Status | Notes |
| --- | --- | --- | --- |
| LOCAL clean results (9) | `exoplanet-detection-period`, `data-to-d3`, `flink-query`, `python-scala-translation`, `organize-messy-files`, `dialogue-parser`, `paper-anonymizer`, `pddl-airport-planning`, `sec-financial-report` | Existing publication retained unchanged | These entries and their repaired bundles, original/repaired runs, raw trajectories, and prior submission records were not rewritten. |
| SERVER audited ACCEPT (2) | `lab-unit-harmonization`, `dynamic-object-aware-egomotion` | `S5_FAIL` | Frozen `final_main31_v1` execution; complete original and repaired formal evidence is included. |
| Historical invalidated canary | `dialogue-parser` server canary | `INVALIDATED` | `dialogue-parser.json` is retained only as an explicitly invalidated audit record. It is not part of the effective submission and does not invalidate the LOCAL dialogue chain. |
| Ownership-conflict evidence | `paper-anonymizer` server PASS | `RETAINED_SEPARATELY` | Kept as independent evidence only; excluded from `submission.json` because LOCAL ownership conflicts with the server result. |

The effective `submission.json` contains the nine existing LOCAL entries plus the two SERVER entries. It does not contain the invalidated server dialogue canary or the ownership-conflict paper result.

Each published task includes `repaired_skill`, `original_run`, and `repaired_run` with the native executor request, result, benchmark result, and ACP trajectory. The trajectories under `trajectory_timelines/` were generated by the official `export_trajectory.py`; `trajectory_timeline_index.json` is generated by that script and was not hand-authored.

The per-task summaries and provenance records are derived publication metadata, not replacements for canonical evidence. No canonical ledger, Skill bundle, task source, verifier, or verdict was modified. Verifier/Gold materials, hidden tests, credentials, and unrelated server workspace files are not published.
