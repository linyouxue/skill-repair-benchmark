IPython – notes for fuzzing / robustness testing

High-value files
- IPython/core/inputtransformer2.py: TransformerManager (token & line transforms)
- IPython/core/splitinput.py: split_user_input() (CLI-style parsing)
- IPython/core/completer.py: split_line() (cursor-position based splitting)

Functions / methods to target
- IPython.core.inputtransformer2.TransformerManager.transform_cell(cell: str) -> str
  - Transforms IPython syntax (magics, prompts, etc.) into valid Python.
- IPython.core.inputtransformer2.TransformerManager.check_complete(cell: str)
  - Determines whether the input is complete; parser/tokenization boundary.
- IPython.core.splitinput.split_user_input(line: str)
  - Splits lines into (pre, cmd, post) style; pure string parsing.

Existing tests and likely oracles (from tests/)
- tests/test_inputtransformer2*.py exercises transform/check_complete.
- tests/test_splitinput.py exercises split_user_input.
- Fuzz-friendly oracles:
  - No-crash / no-hang for arbitrary unicode strings.
  - transform_cell output should be a string and reasonably bounded (avoid explosive growth).

Expected/acceptable exceptions for malformed input
- SyntaxError / IndentationError
- tokenize.TokenError
- ValueError

Seed ideas
- IPython-like prompts and magics:
  - '%time x\n', '!ls\n', 'In [1]: x=1\n', '...: pass\n'
- Mixed indentation, backslashes, and unicode edge cases
